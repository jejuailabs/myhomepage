# 04. 기술 스택 & 핵심 기능 상세

## 기술 스택
- **프레임워크**: Next.js (App Router), Vercel 배포
- **백엔드**: Firebase — Firestore, Auth(Google), Storage, Cloud Functions
- **스타일**: Tailwind CSS
- **모바일 우선**: 전체 뷰포트 기준 max-width 480px 프레임 안에서 디자인, 데스크톱은 해당 프레임을 중앙 정렬로 확장 표시(우선순위 낮음)

## mp3 자동재생 처리 (중요)

### 동작 원칙
1. 메인 허브에서 카드를 **클릭/탭해서** 개별 홈피로 진입한 경우
   → 클릭 이벤트가 곧 유저 인터랙션이므로, 페이지 진입과 동시에 `audio.play()` 호출 시 자동재생 성공 확률이 높음
   (라우팅 전환 시 클릭 컨텍스트를 유지하려면 Next.js 클라이언트 라우팅 + play() 호출을 클릭 핸들러 체인 안에서 트리거하는 방식 권장)
2. **URL 직접 접속(공유 링크, 새로고침 등)**의 경우 브라우저가 자동재생을 차단할 수 있음
   → 폴백 UI: 화면 진입 시 하단에 "🔊 소리 켜고 보기" 형태의 플로팅 버튼을 1회 노출,
     탭하면 그 시점에 재생 시작 (사용자 인터랙션 확보)
3. 음소거(muted) 자동재생은 정책상 허용되나, 이 프로젝트는 mp3 콘텐츠 자체가 핵심이므로
   음소거 자동재생보다는 위 2번의 "재생 유도 버튼" 방식을 기본으로 채택

### UI
- 재생 중에는 화면 우측 하단(또는 상단)에 작은 재생/일시정지 토글 아이콘 상시 노출
- 재생바/진행시간은 노출하지 않음 (미니멀하게 아이콘만)

## 관리자 모드
- 관리자 로그인 시 `/admin` 접근 가능
- 기능: 유저 승인/반려, 메인 허브 카드 노출 순서 수동 정렬, 부적절 콘텐츠 게시 중단
- 일반 유저는 본인 프로필만 수정 가능 (RLS 개념을 Firestore Security Rules로 구현: `uid == resource.data.uid`)

## 다크/라이트 모드 — ⚠️ 확인 필요
- 메인 허브: 다크/라이트 토글 적용 예정 (기본 스택 정책)
- 개별 홈피: 6종 컨셉이 각자 고정된 팔레트(예: 다크 포레스트, 라벤더 파스텔 등)를 갖고 있어
  라이트/다크 토글과 개념적으로 충돌 가능
  → **개별 홈피는 다크/라이트 토글을 비활성화하고 컨셉 고유 팔레트를 고정 유지**하는 것을 기본안으로 제안합니다.
  이 부분 확정해주시면 스펙 업데이트하겠습니다.

## i18n
- 이 프로젝트는 사실상 로컬(조천리) 커뮤니티 대상이라 한국어 단일 언어로 충분해 보입니다.
- 다만 기존 표준 스택에 next-intl이 포함되어 있어, 구조만 대비해두고 실제 다국어 리소스 파일은
  1차 릴리즈에서 작성하지 않는 것을 제안합니다. (필요시 후속 확장)
